DIAGNOSIS
  `git show` emits blob bytes (LF, as stored). The worktree copies are CRLF on
  Windows because core.autocrlf rewrites on checkout. A diff built between a
  LF 'old' file and a CRLF 'new' file describes every line as changed and its
  context cannot match the blob, so `git apply` rejects it.

  Fix for the patch builder: normalise BOTH sides to LF before diffing, so the
  patch is expressed in the same line endings git stores. This is a defect in
  my patch-generation script, not in the proposed change.
