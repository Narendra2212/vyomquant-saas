  D32-1  CONFIRMED -- EXECUTED REPRODUCTION
     All 5 health checks failed. deploy.sh exited 0 and printed the success
     banner, and never printed 'Health check passed'.
     Source basis: the retry loop at :61-68
       for i in {1..5}; do if curl -sf $HEALTH_URL >/dev/null; then ...; break; fi
       echo attempt; sleep 10; done
     has no post-exhaustion branch, and `set -e` cannot fire because curl's
     nonzero status is consumed by the `if` condition.

  D32-2  missing .env.staging: CONFIRMED -- EXECUTED REPRODUCTION
     exit=0 complete=True
     Source basis :21  export $(grep -v '^#' .env.$ENVIRONMENT | xargs)
     grep's failure is confined to a command substitution; `export` with no
     operands returns 0, so `set -e` observes success.

  D38-1  curl absent from PATH: exit=0 complete=True
     A missing health-check client and a failing health check are
     indistinguishable: both traverse the same unguarded loop.

  D38-2  image identity actually handed to Kubernetes
     no tag argument       -> exit=0  SETIMAGE: set image deployment/trading-backend backend=latest -n staging
     empty tag argument    -> exit=0  SETIMAGE: set image deployment/trading-backend backend=latest -n staging
     junk tag argument     -> exit=0  SETIMAGE: set image deployment/trading-backend backend=not-a-digest!! -n staging
     An EXPLICITLY EMPTY tag is silently promoted to `latest`:
     `IMAGE_TAG=${2:-latest}` at :9 uses the default for unset AND null,
     so passing '' does not fail -- it selects the mutable tag.
     A syntactically invalid tag is accepted and deployed: there is no
     digest validation, no tag-shape check, and no rejection path.
     :46-47 `backend=$IMAGE_TAG` is unquoted and never digest-validated.

  D38-3  .env with ordinary quoted values containing spaces: exit=0 -- tolerated (exit 0)
     :21 `export $(grep -v '^#' .env.$ENVIRONMENT | xargs)` word-splits the
     substitution result, so `QUOTED="a value with spaces"` becomes several
     words and `export` rejects the ones that are not identifiers. This is
     an availability defect on well-formed configuration, not a security one.
  D38-4  .env containing $(...): exit=1  substitution ACTUALLY executed = False
     NOT an injection. The marker file was never created, so the
     substitution did not run. `export $(...)` applies word splitting and
     globbing to the result but does NOT re-run command substitution.
     An earlier revision of this harness grepped stdout for the marker
     and reported evaluation; that matched `export`'s own error message
     echoing the token back. That reading is WITHDRAWN.
